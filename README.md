# BRUSSELS — приложение водителя такси (проект VPA)

Мобильное PWA-приложение водителя такси: выход на линию, входящие заказы с таймером,
маршрут к клиенту, платное ожидание, чат с клиентом, поездка, оплата, статистика и история.
Сейчас это **работающий frontend-прототип без backend**: заказы, клиенты и оплата
симулируются demo-движком, а все сервисы спрятаны за интерфейсами, чтобы позже
подключить настоящий сервер.

Основная платформа — iPhone (Safari + «На экран Домой»), также работает в Android Chrome и на десктопе.

---

## Технологии

| Слой | Что используется |
|---|---|
| UI | React 18, TypeScript, Tailwind CSS 3 |
| Сборка | Vite 5 |
| Карта | Leaflet + OpenStreetMap (тайлы CARTO), маршруты — OSRM |
| PWA | `manifest.webmanifest`, собственный Service Worker (`public/sw.js`), иконки, splash screens для iPhone |
| Браузерные API | Geolocation, Notifications (через Service Worker), Web Audio, Vibration, Screen Wake Lock, App Badge |
| Состояние | собственный store + `useSyncExternalStore`, сохранение в localStorage |

Внешних UI-библиотек нет: графики, иконки и анимации написаны вручную.

## Быстрый старт

Нужен Node.js 18+ (рекомендуется 20).

```bash
npm install        # установить зависимости
npm run dev        # dev-сервер: http://localhost:5173 (и адрес в локальной сети для телефона)
npm run build      # проверка TypeScript + production-сборка в dist/
npm run preview    # посмотреть production-сборку: http://localhost:4173
```

Дополнительно:

```bash
npm run build:fast # сборка без проверки типов
npm run typecheck  # только проверка TypeScript
npm run lint       # ESLint
```

> Service Worker регистрируется только в production-сборке (`npm run build` → `npm run preview`
> или GitHub Pages), чтобы не мешать горячей перезагрузке при разработке.

### Открыть с iPhone во время разработки
`npm run dev` выводит адрес вида `http://192.168.x.x:5173`. Откройте его в Safari на iPhone
(телефон и компьютер в одной Wi-Fi сети). Геолокация и уведомления в Safari требуют HTTPS,
поэтому полноценно их проверять удобнее на GitHub Pages.

## Деплой на GitHub Pages

В проекте уже есть workflow `.github/workflows/deploy.yml`.

1. Создайте репозиторий на GitHub и загрузите проект в ветку `main`:
   ```bash
   git init
   git add .
   git commit -m "BRUSSELS driver app"
   git branch -M main
   git remote add origin https://github.com/<user>/<repo>.git
   git push -u origin main
   ```
2. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Каждый push в `main` собирает и публикует приложение. Адрес появится во вкладке **Actions**
   и в Settings → Pages: `https://<user>.github.io/<repo>/`.

`vite.config.ts` использует `base: './'` — сборка работает в любом репозитории без правки путей.
Шаг проверки типов в workflow помечен как `continue-on-error`: если TypeScript найдёт
замечание, деплой всё равно пройдёт, а ошибка будет видна в логах Actions.

## Установка на iPhone (PWA)

1. Откройте адрес GitHub Pages в **Safari**.
2. Нажмите **Поделиться** → **На экран «Домой»** → **Добавить**.
3. Запускайте BRUSSELS с иконки: приложение откроется в standalone-режиме без панели Safari,
   с собственным splash screen и учётом «чёлки»/Dynamic Island (safe-area).
4. Разрешите геолокацию при выходе на линию и уведомления в **Профиль → Уведомления**.

## Demo-режим: полный цикл без клиента

Demo-режим включён по умолчанию (**Профиль → Demo-режим**). На главном экране над панелью
заказа есть строка **DEMO** с кнопками. Кнопка следующего логичного шага подсвечена.

| Кнопка | Что делает |
|---|---|
| **Заказ** (SIMULATE ORDER) | создаёт входящий заказ (первый — точный пример: Rue de la Loi 16 → Brussels Airport) |
| **Доехать** (SIMULATE ARRIVAL) | принимает заказ при необходимости и «ведёт» машину по маршруту к клиенту |
| **Поездка** (SIMULATE TRIP) | сажает клиента, начинает поездку и едет к точке назначения |
| **Оплата** (SIMULATE PAYMENT) | завершает поездку и/или подтверждает оплату |
| **Сообщение** (SIMULATE MESSAGE) | клиент пишет в чат: уведомление, звук, бейдж |
| **Клиент отменил** | отмена заказа клиентом |

Полный цикл: **Заказ → Принять → Доехать → Я на месте → (ожидание) → Поездка → Завершить → Оплата → Статистика**.

Также в demo-режиме:
- при выходе на линию заказы приходят **автоматически** каждые 15–30 секунд (можно отключить);
- клиент отвечает на быстрые ответы в чате и сам пишет через ~25 секунд ожидания;
- статистика за прошлые 30 дней заполнена demo-историей; **сегодняшний день** считается только по вашим действиям;
- **Профиль → Сбросить все данные** очищает всё и создаёт demo-историю заново.

### Позиция водителя
**Профиль → Источник позиции**:
- **Авто** (по умолчанию): реальный GPS, если вы в радиусе 60 км от Брюсселя, иначе demo-позиция в Брюсселе;
- **GPS**: всегда реальный GPS (заказы будут генерироваться в Брюсселе, расстояния станут большими);
- **Demo**: всегда Брюссель, GPS не включается.

Если вы находитесь не в Брюсселе, в режиме «Авто» всё работает на demo-позиции, а реальный GPS
используется, как только вы окажетесь в Брюсселе.

## Как устроены основные функции

**Входящий заказ.** Полноэкранная карточка (slide-up + scale), повторяющийся звонок,
вибрация (где поддерживается), таймер ответа (по умолчанию 15 с) — заливка кнопки
«ПРИНЯТЬ ЗАКАЗ» темнеет по мере истечения времени. Без ответа заказ уходит в `EXPIRED`.

**State machine заказа** (`src/services/orderEngine.ts`):
`NEW → OFFERED → ACCEPTED → DRIVING_TO_PICKUP → ARRIVED → WAITING → PASSENGER_ONBOARD → TRIP_STARTED → TRIP_COMPLETED`,
плюс `CANCELLED_BY_DRIVER`, `CANCELLED_BY_PASSENGER`, `NO_SHOW`, `EXPIRED`.
Недопустимые переходы блокируются таблицей `TRANSITIONS`. Каждый статус — отдельное
состояние нижней панели; хронология статусов сохраняется в истории заказа.

**Прибытие.** В 100 м от точки подачи — «Вы почти на месте», в 30 м — автоматически «Вы на месте».
Кнопка **Я НА МЕСТЕ** доступна всегда и запускает ожидание.

**Ожидание.** Бесплатное время (по умолчанию 3 мин) отсчитывается назад, затем
«ОЖИДАНИЕ ОПЛАЧИВАЕТСЯ», платный таймер и сумма по ставке (по умолчанию €0.30/мин).
После бесплатного ожидания доступна кнопка «Клиент не пришёл» (`NO_SHOW` + компенсация €5).
Значения меняются в **Профиль → Ожидание**.

**Поездка.** Скорость, пройденное расстояние (по GPS/симуляции), время, текущая стоимость,
ETA и адрес назначения. Итог: тариф + ожидание = к оплате. Безналичная оплата подтверждается
автоматически через 3 с, наличные — кнопкой «НАЛИЧНЫЕ ПОЛУЧЕНЫ».

**Тариф demo** (`src/utils/tariff.ts`): €2.40 посадка + €0.95/км + €0.17/мин, минимум €8, аэропорт +€2.

**GPS.** `navigator.geolocation.watchPosition` с троттлингом по режиму:
Высокая (1 с), Баланс (3 с / 8 м), Экономия (10 с / 30 м). GPS включается только на линии
или при активном заказе. Пока водитель на линии, экран не гаснет (Screen Wake Lock).

**Офлайн.** Баннер OFFLINE/ONLINE, состояние сохраняется локально, приложение и уже
загруженные тайлы карты работают из кэша Service Worker, маршрут без сети строится оценкой.

## Карта

Своя карта — Leaflet + OpenStreetMap. Переключатель «Карта / Google / Waze» вверху экрана
выбирает навигатор: Google Maps и Waze **нельзя встроить** в веб-приложение без платного API,
поэтому кнопка «Навигатор» открывает маршрут в их приложении (universal links).

Замена провайдера карты: реализуйте интерфейс `MapProvider` (`src/map/MapProvider.ts`) —
например `GoogleMapsProvider` или `MapboxProvider` — и подставьте его в `src/map/MapView.tsx`.

Маршрутизация: `src/services/routing.ts`, интерфейс `RoutingProvider`. Сейчас используется
публичный demo-сервер OSRM (без ключа, с ограничениями нагрузки) с автоматическим запасным
вариантом. Для продакшена — свой OSRM, Google Directions или Mapbox Directions.

Тайлы: `TILES` в `src/map/LeafletProvider.ts` (CARTO dark / voyager). Для коммерческой
нагрузки нужен собственный тайл-сервер или тариф провайдера.

## Уведомления

`src/notifications/NotificationService.ts`:
- методы `notifyNewOrder`, `notifyNewMessage`, `notifyArrival`, `notifyWaiting`, `notifyTripStarted`, `notifyTripCompleted`, `notifyOrderCancelled`;
- события `NEW_ORDER, NEW_MESSAGE, DRIVER_ARRIVED, WAITING_STARTED, WAITING_PAID, TRIP_STARTED, TRIP_COMPLETED, ORDER_CANCELLED`;
- в открытом приложении — внутренний toast + звук (Web Audio) + вибрация;
- в свёрнутом приложении — системное уведомление через Service Worker;
- **fallback**, если системные уведомления недоступны: toast, звук, мигающий заголовок вкладки, бейдж на иконке.

Транспорт вынесен в интерфейс `NotificationTransport`. Чтобы подключить Firebase Cloud Messaging
или Web Push (VAPID), реализуйте новый транспорт и подключите его в `src/services/index.ts`;
обработчик `push` в `public/sw.js` уже есть.

### Ограничения iPhone, которые важно знать
- **Vibration API в Safari/iOS не поддерживается** — на iPhone вместо вибрации звук и анимация (в Android вибрация работает).
- **Звук** разрешён только после первого касания экрана — приложение «разблокирует» его на первом тапе.
- **Системные уведомления** на iPhone работают только у PWA, добавленного на экран «Домой» (iOS 16.4+).
- **Push при закрытом приложении** требует сервера (Web Push / FCM) — в прототипе подготовлена архитектура.
- **Фоновая геолокация**: iOS останавливает GPS, когда PWA свёрнуто или экран заблокирован. Это ограничение платформы, а не приложения; полностью решается только нативным приложением.

## Архитектура

```
src/
  components/     UI: панели заказа, входящий заказ, итог поездки, чат, навигация, графики
  pages/          Home, Orders (история), Stats, Messages, Profile
  hooks/          состояние, таймеры, GPS, сеть, wake lock
  services/       OrderEngine (state machine), routing, sound, haptics, composition root
  store/          store, сохранение (StorageAdapter → localStorage)
  map/            MapProvider, LeafletProvider, MapView, внешние навигаторы
  notifications/  NotificationService + NotificationTransport
  demo/           DemoEngine — симуляция движения, клиента, оплаты
  data/           locations, customers, drivers, orders (тестовые данные Брюсселя)
  utils/          гео-расчёты, тариф, форматирование, i18n (RU/EN), статистика
  types/          общие типы
```

Точки подключения настоящего backend:

| Что | Где | Как |
|---|---|---|
| Заказы в реальном времени | `OrderSource` в `orderEngine.ts` | WebSocket / Supabase Realtime / Firebase вызывают `orderEngine.createOffer()` |
| Сохранение и синхронизация | `StorageAdapter` в `store/persistence.ts` | IndexedDB или Supabase/Firebase вместо localStorage |
| Push | `NotificationTransport` | FCM / Web Push |
| Карта | `MapProvider` | Google Maps / Mapbox |
| Маршруты | `RoutingProvider` | свой OSRM / Google / Mapbox |
| Авторизация водителей | `data/drivers.ts` → профиль из backend | Supabase Auth / Firebase Auth |

## Сохранение данных

В localStorage (`vpa-brussels:v1`) сохраняются: состояние водителя, текущий и входящий заказ,
история заказов, сообщения, смены (время онлайн), настройки (звук, вибрация, уведомления,
GPS, тема, язык, единицы, ожидание). После перезагрузки приложение продолжает с того же места —
в том числе посреди поездки или ожидания.
